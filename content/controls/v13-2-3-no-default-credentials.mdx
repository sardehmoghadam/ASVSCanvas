## What This Control Means

Where a credential is still needed for service authentication, the credential in use must not be a factory default — not root/root, admin/admin, or any vendor-shipped username/password pair.

## Why This Matters

Default credentials are public knowledge: every scanner, botnet, and casual attacker knows them. Leaving one in place is effectively leaving the door key under the mat with a sign pointing to it. Changing defaults on first use is the cheapest hardening step with the highest return.

## Main Security Requirement

> Verify that if a credential has to be used for service authentication, the credential being used by the consumer is not a default credential (e.g., root/root or admin/admin).

In practice this means no factory-set credentials anywhere in the environment.

## Common Failure Patterns

- **Default creds unchanged** — root/root, admin/admin left as-is.
- **Vendor defaults** — appliance/DB shipped creds not rotated.
- **Default in config** — sample/default secret in deployment files.
- **Same password reused** — "admin" with a guessable variant.

## Secure Implementation

Force a unique credential at provisioning and reject defaults:

```javascript
function provisionServiceAccount({ username, password }) {
  const DEFAULT_CREDS = new Set(["root", "admin", "admin123", "password"]);
  const isDefault = DEFAULT_CREDS.has(username?.toLowerCase())
    || DEFAULT_CREDS.has(password?.toLowerCase());
  if (isDefault) {
    throw new Error("default credentials are not permitted"); // fail closed
  }
  return createAccount({ username, password: hash(password) });
}
```

## Key Rules

- Never ship or run with default credentials.
- Generate unique credentials at provisioning time.
- Reject known default username/password pairs.
- Rotate any credential suspected of being a default.
- Scan configs and secrets for default values in CI.

## Checklist for Code Review

- Are any default credentials present in configs?
- Are factory-set usernames/passwords changed?
- Do provisioning paths reject default values?
- Is there CI scanning for known defaults?
- Are unique credentials generated per deployment?
