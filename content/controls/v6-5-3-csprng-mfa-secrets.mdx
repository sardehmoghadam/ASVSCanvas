## What This Control Means

Every MFA-related secret the application generates — lookup/backup codes, out-of-band codes, and TOTP seeds — must come from a cryptographically secure PRNG. Values must be unguessable and unpredictable, never derived from `Math.random()`, timestamps, or counters.

## Why This Matters

A predictable generator is the root flaw that nullifies MFA: if an attacker can reproduce the code sequence (or the seed that generates it), they bypass the factor entirely without ever interacting with the user's device. CSPRNG sources resist prediction, so the security of the factor rests on the generator's strength.

## Main Security Requirement

> Verify that lookup secrets, out-of-band authentication codes, and time-based one-time password seeds, are generated using a Cryptographically Secure Pseudorandom Number Generator (CSPRNG) to avoid predictable values.

In practice this means using `crypto.randomBytes` (or an OS CSPRNG), never `Math.random`.

## Common Failure Patterns

- **`Math.random()` / `rand()`** — predictable generators for codes/seeds.
- **Time-based codes** — values derived from the clock, guessable.
- **Sequential codes** — incrementing counters rather than random values.
- **Weak seeding** — PRNG seeded with a timestamp or small value.

## Secure Implementation

Generate TOTP seeds and backup codes from a CSPRNG:

```javascript
import { randomBytes } from "node:crypto";
import { authenticator } from "otplib";

function generateTotpSecret() {
  return authenticator.generateSecret(); // uses crypto secure randomness
}

function generateBackupCodes(n = 10) {
  const alphabet = "23456789ABCDEFGHJKLMNPQRSTUVWXYZ";
  return Array.from({ length: n }, () =>
    Array.from({ length: 10 }, () =>
      alphabet[randomBytes(1)[0] % alphabet.length]
    ).join("")
  );
}
```

## Key Rules

- Generate all MFA secrets/codes with a CSPRNG.
- Source randomness from the OS/`crypto.randomBytes`, never `Math.random`.
- Avoid time-, counter-, or timestamp-derived values.
- Ensure the seed has sufficient entropy for its length.
- Review third-party SDKs to confirm they use secure randomness.

## Checklist for Code Review

- Are TOTP seeds generated with a CSPRNG?
- Are lookup codes and OOB codes CSPRNG-generated?
- Is `Math.random`/non-crypto `rand` absent from generation paths?
- Are code values unpredictable and non-sequential?
- Is randomness sourced from the OS CSPRNG?
