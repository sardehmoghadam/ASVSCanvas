## What This Control Means

The application must not offer password hints ("What's your mother's maiden name?") or knowledge-based authentication — secret questions used for login or recovery. These mechanisms must simply not exist in the product.

## Why This Matters

Secret questions are effectively additional weak passwords: the answers are low-entropy, publicly discoverable (birthplace, school, pet's name), and frequently reused. They weaken the account by providing an easier, guessable path around the real password. Removing them eliminates a class of bypass that predates modern password guidance.

## Main Security Requirement

> Verify that password hints or knowledge-based authentication (so-called secret questions) are not present.

In practice this means no UI, no stored answers, and no backend field for KBA.

## Common Failure Patterns

- **Registration quizzes** — collecting "security questions" at signup.
- **Recovery via KBA** — resetting a password by answering a question.
- **Hint prompts** — displaying a stored hint on the login screen.
- **Legacy fields** — answers still in the DB and honored somewhere.

## Secure Implementation

Remove KBA entirely and use secure recovery (V6.4.3) instead:

```javascript
// Do not implement:
//   user.securityQuestion = "..."
//   user.securityAnswer = hash("...")

// Recovery should rely on verified channels + MFA, never trivia.
async function forgotPassword(email) {
  const user = await findByEmail(email);
  await issueResetToken(user); // delivered to a verified channel
}
```

## Key Rules

- Do not collect or store password hints or secret questions.
- Do not use knowledge-based authentication for login or recovery.
- Remove any legacy hint/KBA UI and backend fields.
- Replace KBA with verified-channel + MFA-based recovery.
- Audit for KBA remnants in code and data.

## Checklist for Code Review

- Are password hints present anywhere in the product?
- Are secret questions/KBA used for login or recovery?
- Are any KBA answer fields still stored or honored?
- Is recovery implemented via secure tokens/MFA instead?
- Is there any registration UI collecting security questions?
