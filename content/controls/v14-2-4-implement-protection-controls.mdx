## What This Control Means

The protection controls specified in each data-protection level's documentation — encryption, integrity verification, retention, logging rules and log access, privacy measures — must actually be implemented, not just written down.

## Why This Matters

Documentation is only worth something if it's realized in code. When the written profile says "encrypt at rest" but the code writes plaintext, the classification was theater. This control closes the loop: the implemented behavior must match the documented requirements for each protection level, verified in the running system.

## Main Security Requirement

> Verify that controls around sensitive data related to encryption, integrity verification, retention, how the data is to be logged, access controls around sensitive data in logs, privacy and privacy-enhancing technologies, are implemented as defined in the documentation for the specific data's protection level.

In practice this means code that enforces the documented per-level rules.

## Common Failure Patterns

- **Policy/impl drift** — documented rules not in code.
- **Plaintext despite "encrypt"** — at-rest rule unimplemented.
- **No integrity check** — writes lack verification on read.
- **Retention ignored** — no purge job despite policy.

## Secure Implementation

Implement the documented rules straightforwardly per level:

```python
from cryptography.fernet import Fernet

def store_restricted(record: dict) -> None:
    # documented: encrypt at rest + verify integrity on read
    token = Fernet(key).encrypt(json.dumps(record).encode())
    self.db.set(record["id"], token)          # ciphertext, not plaintext

def read_restricted(record_id: str) -> dict:
    token = self.db.get(record_id)
    try:
        data = Fernet(key).decrypt(token)     # integrity + confidentiality
        return json.loads(data)
    except Exception:
        raise IntegrityError("tampered or corrupt record")
```

## Key Rules

- Implement encryption exactly as documented per level.
- Verify integrity of persisted sensitive data on read.
- Enforce retention/deletion rules in automated jobs.
- Apply documented logging and log-access controls.
- Use the specified privacy-enhancing technologies.

## Checklist for Code Review

- Does code match the documented protection profile?
- Is at-rest encryption actually applied where required?
- Is integrity verification implemented on read?
- Are retention/deletion jobs running as documented?
- Are logging and log-access rules enforced in code?
