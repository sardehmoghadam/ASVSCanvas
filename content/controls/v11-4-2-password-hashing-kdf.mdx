## What This Control Means

Passwords must be stored using an approved, computationally intensive key derivation function (a password hashing function such as Argon2id or bcrypt) with parameters tuned to current guidance, balancing security and performance so brute-force attacks stay costly.

## Why This Matters

Fast hashes like SHA-256 let an attacker test billions of passwords per second, turning a leaked database into a near-instant credential dump. A memory- and CPU-hard KDF with tuned parameters raises the cost per guess so dramatically that offline cracking becomes impractical, even against well-equipped attackers.

## Main Security Requirement

> Verify that passwords are stored using an approved, computationally intensive, key derivation function (also known as a password hashing function), with parameter settings configured based on current guidance. The settings should balance security and performance to make brute-force attacks sufficiently challenging for the required level of security.

In practice this means a KDF with explicit, up-to-date work factors.

## Common Failure Patterns

- **Fast hash** — SHA-256/MD5 used directly on passwords.
- **Default parameters** — KDF left at weak library defaults.
- **Unkeyed/unsalted** — no per-password salt.
- **Static parameters** — work factors never re-tuned over time.

## Secure Implementation

Store passwords with an approved KDF and explicit parameters:

```javascript
import argon2 from "argon2";

async function hashPassword(password) {
  return argon2.hash(password, {
    type: argon2.argon2id,
    memoryCost: 65536, // KiB
    timeCost: 3,       // iterations
    parallelism: 1,
  });
}

async function verifyPassword(hash, password) {
  return argon2.verify(hash, password);
}
```

## Key Rules

- Use an approved password KDF (Argon2id, bcrypt, scrypt).
- Configure memory/iteration parameters per current guidance.
- Always salt each password uniquely.
- Re-tune work factors as hardware improves.
- Never use general-purpose hashes for passwords.

## Checklist for Code Review

- Is an approved, computationally-intensive KDF used?
- Are parameters set per current guidance?
- Is each password uniquely salted?
- Are work factors revisited periodically?
- Are fast hashes used anywhere on passwords?
