## What This Control Means

Password input fields must mask what the user types — the browser-native `type="password"` behavior — so onlookers cannot read the secret. Optionally, the application may let the user reveal the whole masked value or the last typed character on demand, to make long-password entry less error-prone.

## Why This Matters

Shoulder-surfing and screen capture remain cheap, real-world leaks. Masking is the standard defense. But masking also makes typos likely, which pushes users toward short passwords; an optional temporary reveal keeps long passphrases usable without permanently displaying the secret.

## Main Security Requirement

> Verify that password input fields use type=password to mask the entry. Applications may allow the user to temporarily view the entire masked password, or the last typed character of the password.

In practice this means an `input` of type `password`, with show/hide as an optional NIC.

## Common Failure Patterns

- **Plain-text inputs** — `type="text"` used for the password field.
- **No reveal, no confirm** — no way to check a long entry before submit.
- **Permanent reveal** — the "show" toggle leaves the value visible by default.
- **Autocomplete broken** — disabling autocomplete/paste on password fields (see V6.2.7).

## Secure Implementation

Use the native field type and an explicit, opt-in reveal toggle:

```html
<label>Password
  <input type="password" id="password" autocomplete="current-password" />
</label>
<button type="button" data-reveal-for="password">Show</button>
```

```javascript
const toggle = document.querySelector("[data-reveal-for='password']");
toggle.addEventListener("click", () => {
  const input = document.getElementById("password");
  input.type = input.type === "password" ? "text" : "password";
});
```

## Key Rules

- Use `type="password"` (or an equivalent masked control) for entry.
- Mask by default; never display the secret unless the user opts in.
- Keep any reveal temporary and user-initiated.
- Leave autocomplete and paste enabled for password managers.
- Allow confirming the full value to reduce typos.

## Checklist for Code Review

- Are password fields using `type="password"`?
- Is the secret masked by default?
- Is any reveal toggle opt-in and temporary?
- Does the reveal revert to masking after submit/focus loss?
- Are paste and autocomplete left functional?
