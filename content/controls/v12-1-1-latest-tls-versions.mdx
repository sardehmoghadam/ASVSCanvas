## What This Control Means

Only the current recommended TLS protocol versions (TLS 1.2 and TLS 1.3) may be enabled, with the newest (TLS 1.3) configured as the preferred option wherever clients support it.

## Why This Matters

Old protocol versions (SSLv3, TLS 1.0, TLS 1.1) carry known flaws — BEAST, POODLE, CBC weaknesses — and no longer provide meaningful security. Enabling only modern versions and preferring the latest eliminates a whole family of downgrade and legacy-protocol attacks before a single byte of application data moves.

## Main Security Requirement

> Verify that only the latest recommended versions of the TLS protocol are enabled, such as TLS 1.2 and TLS 1.3. The latest version of the TLS protocol must be the preferred option.

In practice this means TLS 1.2+ only, with TLS 1.3 preferred.

## Common Failure Patterns

- **Legacy versions enabled** — SSLv3, TLS 1.0, TLS 1.1 left on.
- **Older version preferred** — server negotiates TLS 1.2 over 1.3.
- **Downgrade not blocked** — no anti-downgrade protection.
- **Per-endpoint drift** — some services on older configs.

## Secure Implementation

Constrain and order the enabled protocol versions:

```javascript
const tlsOptions = {
  minVersion: "TLSv1.2",
  maxVersion: "TLSv1.3",
  secureProtocol: "TLS_method",
  // TLS 1.3 is negotiated first when both sides support it
};

const server = https.createServer(tlsOptions, handler);
```

## Key Rules

- Enable only TLS 1.2 and TLS 1.3.
- Prefer TLS 1.3 for all capable clients.
- Disable SSLv3, TLS 1.0, and TLS 1.1.
- Block protocol downgrade below TLS 1.2.
- Keep the version config consistent across every endpoint.

## Checklist for Code Review

- Are only TLS 1.2 and TLS 1.3 enabled?
- Is TLS 1.3 preferred over TLS 1.2?
- Are SSLv3/TLS 1.0/TLS 1.1 fully disabled?
- Is downgrade below TLS 1.2 prevented?
- Is the policy applied to every endpoint?
