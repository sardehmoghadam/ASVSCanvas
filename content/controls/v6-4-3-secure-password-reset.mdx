## What This Control Means

A forgotten password must be recoverable through a secure process, but that process must never let an attacker walk around the MFA the account has enabled. If the account uses multi-factor authentication, losing the password must not let someone skip the second factor to take over the account.

## Why This Matters

Password reset is a top takeover target: it is effectively an alternate route to the same account. If recovery ignores MFA, then every MFA-protected account is only as secure as the weakest reset step. Keeping MFA in the reset loop preserves the reason the user enabled it in the first place.

## Main Security Requirement

> Verify that a secure process for resetting a forgotten password is implemented, that does not bypass any enabled multi-factor authentication mechanisms.

In practice this means reset requires the same (or higher) assurance as normal login, including MFA.

## Common Failure Patterns

- **Reset bypasses MFA** — reset link alone overrides the enrolled factor.
- **Weak fallback** — reset via secret questions or bare email link only.
- **Reset then re-enroll** — attacker resets and registers their own MFA unverified.
- **No rate limiting/expiry** on reset tokens.

## Secure Implementation

Require a verified factor during recovery; issue short-lived, single-use tokens:

```javascript
async function resetPassword(req, res) {
  const { token } = req.body;
  const resetReq = await consumeResetToken(token); // single-use, <=10min
  // MFA still required: verify an enrolled factor before allowing the change.
  await verifyFactor(resetReq.user, req.body.factorProof);
  await setNewPassword(resetReq.user, req.body.password);
}
```

Bind the reset token to the user/session and expire promptly.

## Key Rules

- Implement a secure, self-service forgot-password process.
- Do not let reset bypass enabled MFA.
- Require verification of an enrolled factor during reset.
- Use single-use, short-lived, bound reset tokens.
- Notify the user after the reset (V6.3.7).

## Checklist for Code Review

- Is there a secure forgotten-password recovery flow?
- Does the flow still require MFA when the account has it?
- Are reset tokens single-use, short-lived, and bound to the user?
- Can an attacker re-enroll MFA without verified access?
- Is the user notified after a reset completes?
