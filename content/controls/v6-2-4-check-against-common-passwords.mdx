## What This Control Means

New passwords — whether at registration or change — must be checked against a list of at least the top 3,000 most common passwords (filtered to those that satisfy your length policy). Any password on that list is rejected before it is accepted.

## Why This Matters

The top few thousand passwords (`12345678`, `password1`, `qwertyuiop`) account for a disproportionate share of every credential-stuffing success. A length floor alone does nothing against these — they are long enough but trivially guessable. Blocking the common list removes the easiest wins available to an attacker at registration time.

## Main Security Requirement

> Verify that passwords submitted during account registration or password change are checked against an available set of, at least, the top 3000 passwords which match the application's password policy, e.g. minimum length.

In practice this means a checked-in blocklist plus a normalization-aware comparison.

## Common Failure Patterns

- **No common-password check** — only length/composition enforced.
- **Exact string match only** — `Password1` blocked but `P@ssword1` passes.
- **List too small or unfiltered** — failing to cover passwords meeting the length policy.
- **Check skipped on one path** — registration checks but password change does not.

## Secure Implementation

Normalize and compare against a checked-in list:

```javascript
import COMMON_PASSWORDS from "./common-passwords.js"; // >= 3000 entries

function normalize(pw) {
  return pw.toLowerCase().replace(/[^a-z0-9]/g, "")
    .replace(/0/g, "o").replace(/1/g, "i").replace(/3/g, "e");
}

function isCommon(password) {
  const n = normalize(password);
  return COMMON_PASSWORDS.some(w => normalize(w) === n);
}
```

## Key Rules

- Check new passwords against at least the top 3,000 common passwords.
- Apply the check at both registration and password change.
- Filter the list to those matching your length policy.
- Compare on a normalized basis (case, common substitutions).
- Combine with context-word and breach checks.

## Checklist for Code Review

- Is a common-password list (≥ 3,000) used?
- Is the check applied on registration *and* change?
- Does the list reflect the application's length policy?
- Is comparison normalized against character substitutions?
- Are common passwords rejected before hashing/storage?
