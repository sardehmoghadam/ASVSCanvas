## What This Control Means

When the system creates an initial password or activation code for a new/onboarded account, that secret must be cryptographically random, conform to the normal password policy, and expire quickly — either after a short window or immediately after first use. It is a bootstrap secret, never the user's permanent password.

## Why This Matters

Initial credentials are predictable and frequently left unchanged. A weak generated password (`Welcome123`) or an activation code that never expires becomes a standing backdoor. Forcing CSPRNG randomness and immediate expiry means the bootstrap value is only valid for the instant it is needed, then replaced by a real, user-chosen credential.

## Main Security Requirement

> Verify that system generated initial passwords or activation codes are securely randomly generated, follow the existing password policy, and expire after a short period of time or after they are initially used. These initial secrets must not be permitted to become the long term password.

In practice this means a generated secret plus a one-shot/expiry flag.

## Common Failure Patterns

- **Predictable values** — sequential or `Math.random()`-based codes.
- **Never expires** — activation links/codes valid forever and reusable.
- **Becomes permanent** — the generated password is never forced to change.
- **Ignores policy** — generated secret is shorter or weaker than policy allows.

## Secure Implementation

Generate with a CSPRNG and require change on first use:

```javascript
import { randomBytes } from "node:crypto";

function generateInitialPassword() {
  const alphabet = "ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz23456789";
  const chars = Array.from({ length: 20 }, () => {
    const i = randomBytes(1)[0] % alphabet.length;
    return alphabet[i];
  });
  return chars.join("");
}

// Account is created with:
//   mustChangePassword: true
//   activationExpiresAt: now + 15 minutes
```

## Key Rules

- Generate initial passwords/codes with a CSPRNG.
- Make them satisfy the existing password policy.
- Expire them after a short window or immediately after first use.
- Force a change so they never become the long-term password.
- Mark them single-use and non-reusable.

## Checklist for Code Review

- Are initial passwords/codes generated with a CSPRNG?
- Do they meet the configured password policy?
- Is there a short expiry (time- or use-based)?
- Is the user forced to set a new password on first login?
- Can an initial secret be reused after expiry?
