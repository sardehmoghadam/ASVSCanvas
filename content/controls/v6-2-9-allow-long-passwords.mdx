## What This Control Means

The application must store and verify passwords of at least 64 characters. There can be no silent cap at 16, 32, or 50 characters; a user who chooses a 64-character (or longer) passphrase must be fully supported end to end.

## Why This Matters

Long passphrases are the most effective passwords users actually remember. A system that truncates or rejects them punishes the very users following best practice and shrinks the effective secret to whatever the cap allows. Sixty-four characters is just a floor, not the ideal — the point is that no imposed limit undermines the user's chosen strength.

## Main Security Requirement

> Verify that passwords of at least 64 characters are permitted.

In practice this means validating a 64+ character value works and verifying it unchanged.

## Common Failure Patterns

- **64-char field limits** — HTML `maxlength` or backend slicing at exactly 64.
- **Legacy column/padding** — fixed-width database columns or encryption padding capping length.
- **Client-side cap** — form limit below what the server could accept.
- **Rejection of long values** — explicit "maximum 50 characters" errors.

## Secure Implementation

Set generous, non-limiting constraints and verify the full value:

```javascript
function validatePassword(password) {
  if (password.length < 8) throw new Error("Too short");
  if (password.length > 512) throw new Error("Too long"); // generous limit only
  return true;
}

async function verify(user, submitted) {
  return bcrypt.compare(submitted, user.passwordHash);
}
```

Use a password hash that works on long inputs (bcrypt/argon2), not a hash with practical length limits that would force truncation.

## Key Rules

- Accept passwords of at least 64 characters.
- Do not truncate or cap at a small maximum.
- Keep any upper limit generous (hundreds of characters) and documented.
- Ensure storage and verification handle the full length.
- Test a full 64+ character passphrase end to end.

## Checklist for Code Review

- Can a 64-character password be set and used to log in?
- Is there any truncation or small maximum length enforced?
- Is the field/token limit generous rather than restrictive?
- Does the password hashing algorithm support long inputs?
- Are long-password cases covered by tests?
