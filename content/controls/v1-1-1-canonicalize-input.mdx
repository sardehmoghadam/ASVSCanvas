## What This Control Means

Form and URL-encoded input often leaves the wire still percent-encoded, HTML-entity encoded, or layered under several chained encodings. Canonicalization reduces the value to its single, simplest ("canonical") form exactly once, only when that encoding was actually expected, and strictly before any validation or sanitization runs. Decoding after validation has already passed would let a payload slip through checks in one encoding and be reinterpreted into something dangerous in another.

## Why This Matters

Decoding the same value more than once lets attacker-chosen encodings bypass validation, and a single decode pass performed in the wrong order invalidates downstream checks entirely. When input is validated in one form but consumed in another, every control layered on top of it can be defeated.

## Main Security Requirement

> Verify that input is decoded or unescaped into a canonical form only once, it is only decoded when encoded data in that form is expected, and that this is done before processing the input further, for example it is not performed after input validation or sanitization.

In practice this means decode once, only for sources known to be encoded, and always before you validate or sanitize.

## Common Failure Patterns

- **Decoding after validation** — a value is re-decoded downstream after checks have passed.
- **Multiple decode passes** — double URL-decoding turns `%2527` into a live quote.
- **Decoding unexpected input** — treating plain text as encoded data and mangling it.
- **Mixing forms** — validating the encoded form while consuming the decoded form.

## Secure Implementation

Decode exactly once against a defined policy, then validate the canonical form:

```javascript
// Decode exactly once, then validate; never decode again later in the pipeline.
const raw = req.query.q;                         // e.g. "%27%20OR%201%3D1%27"
const decoded = decodeURIComponent(raw);         // single canonicalization pass

if (!isSafeQueryParam(decoded)) {
  return res.status(400).end();                  // validate/sanitize the canonical form
}
```

## Key Rules

- Decode once, before any validation or sanitization.
- Only decode when the source actually supplies encoded data.
- Never decode the same value a second time later in the pipeline.
- Validate and sanitize the canonical form, not the raw wire form.

## Checklist for Code Review

- Is every value decoded exactly once?
- Does decoding happen before validation and sanitization?
- Is any value ever decoded after validation has run?
- Is decoding limited to sources known to be encoded?
- Is the canonical form the one that is validated and passed downstream?
