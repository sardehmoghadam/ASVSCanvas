## What This Control Means

Lookup (backup) secrets stored in the backend must be protected according to their entropy. Under 112 bits of entropy (~19 random alphanumeric or ~34 random digits), they must be hashed with an approved *password* hash (argon2/bcrypt/scrypt) and a random salt. At or above 112 bits, a standard (fast) hash like SHA-256 is acceptable.

## Why This Matters

Low-entropy secrets are crackable by brute force if the stored form is fast to verify (a plain SHA-256 of a 6-digit code is trivially reversible). A slow, salted password hash raises the cost of cracking weak secrets to infeasible levels. When the secret is genuinely high-entropy, that protection is unnecessary and a simple hash suffices.

## Main Security Requirement

> Verify that, when being stored in the application's backend, lookup secrets with less than 112 bits of entropy (19 random alphanumeric characters or 34 random digits) are hashed with an approved password storage hashing algorithm that incorporates a 32-bit random salt. A standard hash function can be used if the secret has 112 bits of entropy or more.

In practice this means choosing the hash based on measured entropy of the secret.

## Common Failure Patterns

- **Plaintext storage** — backup codes stored raw.
- **Unsalted fast hash** — SHA-256 of a short code (rainbow/brute-forceable).
- **Wrong hash for high entropy** — needlessly expensive or, conversely, weak hash for low entropy.
- **No salt** or a shared/constant salt.

## Secure Implementation

Branch on entropy:

```javascript
import { hash as bcryptHash } from "bcrypt";
import { createHash, randomBytes } from "node:crypto";

async function storeLookupSecret(secret, entropyBits) {
  if (entropyBits < 112) {
    const salt = randomBytes(16); // handled by bcrypt internally
    return bcryptHash(secret, 12);
  }
  return "sha256:" + createHash("sha256").update(secret).digest("hex");
}
```

## Key Rules

- Hash low-entropy (≤112-bit) lookup secrets with argon2/bcrypt/scrypt + salt.
- Use a 32-bit (or stronger) random salt for the password hash.
- Permit a standard hash only when entropy is ≥112 bits.
- Never store lookup secrets in plaintext.
- Measure entropy honestly (random alphanumeric/digits, not human words).

## Checklist for Code Review

- Are lookup secrets stored hashed, not plaintext?
- Are low-entropy secrets using a salted password hash?
- Is the salt random and unique per secret?
- Are only ≥112-bit secrets stored with a standard hash?
- Is the entropy estimate based on actual randomness?
