## What This Control Means

Changing a password must prove you are the legitimate account owner: the flow requires both the current password and the new password. Without the current credential, anyone with a stolen or hijacked session could silently take over the account.

## Why This Matters

A logged-in-but-unattended session, or a CSRF/XSS-compromised tab, must not be able to reset the password unnoticed. Requiring the current password ties the change to a secret that only the account owner knows — re-authentication at the moment of the sensitive change — and prevents an attacker who merely has session access from locking the real user out.

## Main Security Requirement

> Verify that password change functionality requires the user's current and new password.

In practice this means collecting and verifying both values, not just accepting a new one.

## Common Failure Patterns

- **New password only** — accepting a change without the current password.
- **Session-only trust** — assuming an active session is proof enough.
- **Current password checked late** — validating the new password before the current one.
- **No re-auth on sensitive change** — skipping step-up for password rotation.

## Secure Implementation

Verify the current password before persisting the new one:

```javascript
app.post("/account/password", authenticate, async (req, res) => {
  const { current, next } = req.body;
  const ok = await bcrypt.compare(current, req.user.passwordHash);
  if (!ok) {
    return res.status(401).json({ error: "Current password is incorrect" });
  }
  req.user.passwordHash = await bcrypt.hash(next, 12);
  await db.save(req.user);
  res.json({ changed: true });
});
```

## Key Rules

- Require both the current and the new password.
- Verify the current password before accepting the new one.
- Treat a failed current-password check as an authentication failure.
- Apply the same rule to any credential change (email, username).
- Hash the new password with an approved algorithm.

## Checklist for Code Review

- Does the change flow require the current password?
- Is the current password verified before the new one is stored?
- Is re-authentication enforced even with an active session?
- Are failed current-password attempts logged/limited?
- Is the same protection applied to other credential changes?
